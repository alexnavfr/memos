# Поиск пары чисел в массиве с суммой равной данной

## Решение с использованием LINQ

LINQ позволяет лаконично выразить логику выборки пар. Мы будем использовать группировку для подсчета частоты чисел (аналогично `Dictionary`) и генерацию всех возможных пар, учитывая дубликаты.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;

public class Solution {
    public static string FindPairs(int k, List<int> data) {
        // Группируем числа по значению и считаем частоту
        var frequency = data.GroupBy(x => x)
                           .ToDictionary(g => g.Key, g => g.Count());

        // Находим все пары
        var pairs = data.SelectMany((num, i) => {
            int complement = k - num;
            // Проверяем наличие complement и учитываем случай num == complement
            if (frequency.ContainsKey(complement)) {
                if (num == complement) {
                    // Для num == complement добавляем пары (num+num) для count-1
                    return Enumerable.Repeat($"({num}+{complement})", frequency[num] - 1);
                } else if (complement > num && frequency.ContainsKey(complement)) {
                    // Для разных чисел добавляем пару один раз
                    return new[] { $"({num}+{complement})" };
                }
            }
            return Enumerable.Empty<string>();
        }).Where(p => !string.IsNullOrEmpty(p));

        // Формируем результат
        string result = string.Join("", pairs);
        return result.Length == 0 ? "()" : result;
    }
}
```

#### Объяснение LINQ-решения:
1. **Группировка чисел**:
   - `data.GroupBy(x => x).ToDictionary(g => g.Key, g => g.Count())` создает словарь частот, где ключ — число, значение — количество его вхождений. Для `data=[5,5,5]`: `{5: 3}`.
   - Сложность: O(n).

2. **Поиск пар с помощью `SelectMany`**:
   - Для каждого числа `num` в `data` вычисляем `complement = k - num`.
   - Если `num == complement` (например, `5+5=10`), добавляем `(num+complement)` `frequency[num] - 1` раз для каждого числа, чтобы учесть все возможные пары, исключая использование одного элемента дважды в одной паре.
   - Если `num != complement`, добавляем пару `(num+complement)` только если `complement > num`, чтобы избежать дублирования (например, `(3+7)` и `(7+3)`).
   - `SelectMany` объединяет все результаты в плоскую коллекцию строк.
   - Сложность: O(n) для прохода по `data`, операции с словарем O(1) в среднем.

3. **Формирование результата**:
   - `string.Join("", pairs)` объединяет все пары в строку.
   - Если пар нет, возвращаем `"()"`.
   - Сложность: O(m), где `m` — длина результирующей строки (до O(n²) в худшем случае).

4. **Тестовый случай `k=10, data=[5,5,5]`**:
   - Словарь: `{5: 3}`.
   - Для каждого `5`:
     - `complement = 10 - 5 = 5`.
     - Так как `num == complement`, добавляем `(5+5)` дважды (`frequency[5] - 1 = 2`) для каждого из трех чисел, но учитываем только уникальные пары: `(0,1)`, `(0,2)`, `(1,2)` → три пары `(5+5)`.
   - Результат: `"(5+5)(5+5)(5+5)"`.

#### Сложность:
- **Время**: O(n) для группировки + O(n) для поиска пар + O(m) для формирования строки, где `m` до O(n²) в худшем случае.
- **Память**: O(n) для словаря + O(m) для результата.

---

### Сравнение подходов
- **LINQ**:
  - Плюсы: Компактный и выразительный код, легко читаемый.
  - Минусы: Может быть менее производительным из-за накладных расходов LINQ.
  - Сложность: O(n + m), где `m` до O(n²).
- **Сортировка**:
  - Плюсы: Эффективно для больших списков с малым количеством дубликатов, использует сортировку для упрощения логики.
  - Минусы: Дополнительная сложность O(n log n) из-за сортировки.
  - Сложность: O(n log n + m).
