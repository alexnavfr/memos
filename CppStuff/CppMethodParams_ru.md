# Передача параметров в метод разными способами.

## Prompt: _Подробно расскажи разницу в объявлении методов_
```cpp
void doSomeThing( Trade tr);
void doSomeThing( Trade *tr);
void doSomeThing( Trade &tr);
void doSomeThing( const Trade &tr);
void doSomeThing( const Trade *tr);
```

В C++ способы передачи параметров в функции существенно влияют на производительность и использование памяти, особенно когда класс `Trade` занимает большой объем памяти. Рассмотрим различия между приведенными вариантами:

---

### **1. Передача по значению (`void doSomeThing(Trade tr)`)**
```cpp
void doSomeThing(Trade tr);  // Передача по значению
```
#### Особенности:
- Создается **полная копия** объекта `Trade`, что может быть дорогостоящим при большом размере класса.
- Изменения, сделанные внутри функции, **не влияют** на исходный объект.
- Подходит, если нужно работать с локальной копией или модифицировать объект внутри функции без изменения оригинала.

#### Когда использовать:
- Если нужна изолированная копия объекта.
- Если планируется изменять переданный объект внутри функции, но исходный объект должен остаться неизменным.

### **2. Передача по указателю (`void doSomeThing(Trade *tr)`)**
```cpp
void doSomeThing(Trade *tr);  // Передача по указателю
```
#### Особенности:
- Передается **адрес объекта**, а не сам объект (экономит память).
- Можно изменять исходный объект внутри функции (если указатель не `const`).
- Может быть `nullptr`, поэтому нужно проверять валидность указателя.
- Синтаксис работы с указателями (`->` вместо `.`).

#### Когда использовать:
- Если нужно изменять исходный объект.
- Если объект может отсутствовать (указатель может быть `nullptr`).
- В низкоуровневом коде или при работе с полиморфными объектами.

### **3. Передача по ссылке (`void doSomeThing(Trade &tr)`)**
```cpp
void doSomeThing(Trade &tr);  // Передача по ссылке (неконстантной)
```
#### Особенности:
- Передается **ссылка на объект** (аналогично указателю, но с синтаксисом как у значения).
- Изменения внутри функции **влияют** на исходный объект.
- Не может быть `nullptr` (в отличие от указателя).
- Более безопасный и удобный вариант, чем указатель, если объект гарантированно существует.

#### Когда использовать:
- Если нужно изменять исходный объект.
- Если объект всегда существует (нет необходимости в проверке на `nullptr`).

### **4. Передача по константной ссылке (`void doSomeThing(const Trade &tr)`)**
```cpp
void doSomeThing(const Trade &tr);  // Передача по константной ссылке
```
#### Особенности:
- Передается **ссылка на объект**, но его нельзя изменить внутри функции.
- Экономит память (не создает копию) и защищает от случайных изменений.
- Оптимальный вариант для передачи больших объектов, которые не нужно изменять.

#### Когда использовать:
- Если объект **большой** и его не нужно изменять (наиболее частый случай).
- Для защиты от случайной модификации объекта.
- Для передачи временных объектов (rvalue).

### **5. Передача по указателю на константу (`void doSomeThing(const Trade *tr)`)**
```cpp
void doSomeThing(const Trade *tr);  // Указатель на неизменяемый объект
```

#### **Особенности:**
- Передается **указатель на объект**, но сам объект нельзя изменить (аналог `const Trade &`, но с возможностью `nullptr`).
- Экономит память, так как копирования нет.
- Нужно проверять на `nullptr` (в отличие от ссылки).
- Синтаксис: `tr->method()` (как у обычного указателя).

#### **Когда использовать:**
- Если объект **большой** и его не нужно изменять, но он **может отсутствовать** (`nullptr`).
- Для совместимости с C-кодом или API, где используются указатели.
- Если нужно явно подчеркнуть, что объект опционален (может быть `nullptr`).

---

### **Сравнение производительности**
| Способ передачи               | Копирование объекта | Можно изменить объект | Может быть `nullptr` | Оптимальность для большого `Trade` |
|-------------------------------|---------------------|-----------------------|----------------------|------------------------------------|
| `Trade tr` (по значению)      | Да (медленно)       | Только копию          | Нет                  | ❌ Плохо (лишнее копирование)      |
| `Trade *tr` (по указателю)    | Нет                 | Да                    | Да                   | ✅ Хорошо (но нужно проверять)     |
| `Trade &tr` (по ссылке)       | Нет                 | Да                    | Нет                  | ✅ Хорошо (но можно изменить)      |
| `const Trade &tr`             | Нет                 | Нет                   | Нет                  | ✅ **Лучший вариант** (если не надо менять) |
| `const Trade *tr`             | Нет                 | Нет                   | Да                   | ✅ Хорошо (если объект может отсутствовать) |


### **Рекомендации. Когда что использовать?**

1. **`const Trade &tr`** – **основной выбор**, если:
   - объект большой и не должен изменяться,
   - объект гарантированно существует (не `nullptr`),
   - оптимально по скорости и памяти.

2. **`const Trade *tr`** – если:
   - объект может отсутствовать (`nullptr`),
   - нужно явно показать, что параметр опционален,
   - работа с C API или полиморфными объектами.

3. **`Trade &tr`** – если нужно **изменить объект**, и он точно существует.

4. **`Trade *tr`** – если нужно **изменить объект**, но он может отсутствовать.

5. **`Trade tr`** – только если нужна **изолированная копия** (редко для больших объектов). Или объект маленький (например, `int`, `float`).
6. 

#### Примеры:
```cpp
// 1. Оптимально: константная ссылка. Не изменяет объект, экономит память
void printTrade(const Trade &tr) {
    std::cout << tr.getDetails(); // Без копирования
}

// 2. Указатель на константу (объект может быть nullptr)
void validateTrade(const Trade *tr) {
    if (tr) {  // Проверка на nullptr
        std::cout << tr->getDetails();
    }
}

// 3. Изменение объекта через указатель (может быть nullptr)
// объект может отсутствовать
void applyDiscount(Trade *tr, double discount) {
    if (tr) { // Проверка на nullptr
        tr->setPrice(tr->getPrice() * (1 - discount));
    }
}

// 4. Изменяет объект, работает с оригиналом
// объект обязан существовать
void applyDiscount(Trade &tr, double discount) {
    tr.setPrice(tr.getPrice() * (1 - discount));
}

// 5. Передача по значению (редко для больших объектов)
void logTrade(Trade tr) {  // Создается копия
    tr.logToFile();  // Работает с копией
}
```
### **Итог**
- **Лучший вариант для передачи больших объектов без изменений** → `const Trade &tr`.
- **Если объект может отсутствовать** → `const Trade *tr` (для чтения) или `Trade *tr` (для изменения).
- **Передача по значению** (`Trade tr`) — почти никогда не используется для больших объектов.
Выбор способа передачи зависит от семантики использования функции и требований к производительности.
