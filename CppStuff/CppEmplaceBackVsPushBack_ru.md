# Разница `emplace_back` и других `emplace_*` функций перед `push_back`

## Prompt:
__

--- 
### **Преимущества `emplace_back` и других `emplace_*` функций перед `push_back` и `insert`**

Функции `emplace_back`, `emplace`, `emplace_front` и другие аналоги были добавлены в C++11 для повышения эффективности работы с контейнерами (`std::vector`, `std::map`, `std::list` и др.). Их ключевое отличие от традиционных `push_back` и `insert` заключается в **прямом конструировании объекта внутри контейнера**, без лишних копирований или перемещений.

---

## **1. Как работают `push_back` и `insert`?**
Рассмотрим на примере `std::vector`:
```cpp
std::vector<MyClass> vec;

// 1. Создаём временный объект
MyClass obj("Hello");

// 2. Перемещаем его в вектор (если есть перемещающий конструктор)
vec.push_back(std::move(obj));

// ИЛИ копируем (если перемещения нет)
vec.push_back(obj);
```
**Проблемы:**
- Если объект **не поддерживает перемещение**, происходит **лишнее копирование**.
- Даже если есть перемещение, всё равно сначала создаётся временный объект, а затем он перемещается в контейнер.

---

## **2. Как работает `emplace_back`?**
`emplace_back` **конструирует объект прямо внутри контейнера**, используя переданные аргументы:
```cpp
std::vector<MyClass> vec;

// Создаём объект "на месте" внутри вектора
vec.emplace_back("Hello");  // Вызывается конструктор MyClass(const char*)
```
**Что происходит:**
1. Вектор выделяет память (если нужно).
2. **Напрямую вызывается конструктор `MyClass`** с аргументами `"Hello"` в уже выделенной памяти.
3. **Никаких временных объектов, никаких копирований или перемещений!**

---

## **3. Преимущества `emplace_back`**
### **① Экономия на временных объектах**
- `push_back` требует создания объекта **перед** вставкой.
- `emplace_back` создаёт его **уже внутри контейнера**, избегая лишних операций.

### **② Избегание лишних перемещений**
Даже если у объекта есть перемещающий конструктор, `emplace_back` всё равно эффективнее:
```cpp
vec.push_back(MyClass("Hello"));  // 1. Временный объект, 2. Перемещение
vec.emplace_back("Hello");        // 1. Прямое создание внутри
```

### **③ Поддержка агрегатной инициализации**
`emplace_back` может создавать объекты без явного вызова конструктора:
```cpp
struct Point { int x, y; };
std::vector<Point> points;

points.push_back({1, 2});       // До C++11 могло не работать
points.emplace_back(1, 2);      // Работает всегда
```

### **④ Эффективность для "тяжёлых" объектов**
Особенно заметно для:
- Объектов с динамической памятью (`std::string`, `std::vector`).
- Классов без перемещающих операций.
- Объектов с дорогим копированием.

---

## **4. `emplace` vs `insert` в ассоциативных контейнерах**
Аналогичное преимущество есть у `emplace` в `std::map`, `std::set`, `std::unordered_map` и др.:
```cpp
std::map<int, std::string> myMap;

// insert требует создания pair
myMap.insert(std::make_pair(42, "Answer"));  // Копирование/перемещение

// emplace конструирует pair на месте
myMap.emplace(42, "Answer");  // Прямая инициализация
```

---

## **5. Когда `push_back`/`insert` всё ещё полезны?**
1. **Если нужно явно передать существующий объект**:
   ```cpp
   MyClass obj;
   vec.push_back(obj);  // Хотим скопировать
   vec.push_back(std::move(obj));  // Хотим переместить
   ```
2. **Для совместимости с legacy-кодом** (C++98/03).
3. **Если `emplace` усложняет читаемость** (редко, но бывает).

---

## **6. Вывод**
| Критерий            | `push_back`/`insert` | `emplace_back`/`emplace` |
|---------------------|----------------------|--------------------------|
| **Копирования**     | Да (если нет перемещения) | Нет |
| **Перемещения**     | Да (если есть) | Нет |
| **Временные объекты**| Да | Нет |
| **Производительность** | Медленнее | Быстрее |
| **Читаемость**      | Проще | Может быть сложнее |

**Рекомендация:**  
✔ **Всегда используйте `emplace_back`/`emplace`**, если хотите избежать лишних копирований.  
✔ **Используйте `push_back`/`insert`**, только если нужно явно передать существующий объект.
