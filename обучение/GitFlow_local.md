# Local git flow for project

### Prompt:
_Существует удаленный репозиторий на GitHub. Проект Qt|C++, ветка main. Определи необходимые действия с git. Которые должны включать: создание локальной копии, внесение измений, доставка изменений в основную ветку которая уже может измениться. Обьясни классичекий workflow в данном случае. Последовательность действий шаг за шагом._

Для работы с удаленным репозиторием на GitHub и внесения изменений в основную ветку `main`, следуйте классическому Git-workflow. Этот процесс включает создание локальной копии репозитория, внесение изменений в отдельной ветке, и последующее слияние этих изменений в основную ветку. Вот пошаговая инструкция:

### 1. Клонирование репозитория

- **Клонирование**: Создайте локальную копию удаленного репозитория.

  ```bash
  git clone https://github.com/username/repository.git
  cd repository
  ```

### 2. Создание новой ветки для работы

- **Создание ветки**: Создайте новую ветку для внесения изменений. Это позволяет изолировать ваши изменения от основной ветки.

  ```bash
  git checkout -b feature-branch
  ```

### 3. Внесение изменений

- **Редактирование кода**: Внесите необходимые изменения в код.

- **Добавление изменений в индекс**: После внесения изменений добавьте их в индекс.

  ```bash
  git add .
  ```

- **Коммит изменений**: Закоммитьте изменения с осмысленным сообщением.

  ```bash
  git commit -m "Describe the changes made"
  ```

### 4. Обновление локальной ветки `main`

- **Получение обновлений**: Перед слиянием изменений в основную ветку, обновите локальную ветку `main`, чтобы учесть возможные изменения, внесенные другими разработчиками.

  ```bash
  git checkout main
  git pull origin main
  ```

### 5. Слияние изменений

- **Слияние изменений**: Переключитесь обратно на вашу рабочую ветку и объедините изменения из `main`.

  ```bash
  git checkout feature-branch
  git merge main
  ```

- **Разрешение конфликтов**: Если возникнут конфликты, разрешите их вручную, затем добавьте изменения в индекс и закоммитьте.

### 6. Отправка изменений в удаленный репозиторий

- **Отправка ветки**: Отправьте вашу ветку в удаленный репозиторий.

  ```bash
  git push origin feature-branch
  ```

### 7. Создание Pull Request (PR)

- **Создание PR**: Перейдите на GitHub и создайте Pull Request из вашей ветки в `main`. Опишите изменения и дождитесь ревью.

### 8. Слияние Pull Request

- **Ревью и слияние**: После успешного ревью и утверждения, ваш PR будет слит в `main`.

### 9. Обновление локальной ветки `main`

- **Обновление**: После слияния PR, обновите локальную ветку `main`.

  ```bash
  git checkout main
  git pull origin main
  ```

### 10. Удаление ветки (опционально)

- **Удаление ветки**: После успешного слияния и обновления, вы можете удалить локальную и удаленную ветки.

  ```bash
  git branch -d feature-branch
  git push origin --delete feature-branch
  ```

Этот workflow позволяет эффективно управлять изменениями в проекте, минимизируя риск конфликтов и обеспечивая качество кода через ревью.
