# Гарантии исключений (exception safety) для различных операций с контейнерами STL

## Prompt:
_Каковы гарантии исключений (exception safety) для различных операций с контейнерами STL?_

### **Гарантии исключений (exception safety) в STL-контейнерах**

Гарантии исключений определяют, как контейнеры ведут себя при возникновении исключений. В STL есть несколько уровней безопасности:

#### **1. Уровни гарантий исключений**
1. **No-throw guarantee** (не кидает исключений)  
   - Операция никогда не выбрасывает исключений.  
   - Пример: `std::vector::clear()`, `std::array::operator[]` (без проверки границ).  

2. **Strong exception safety (строгая гарантия)**  
   - Если операция завершается исключением, состояние программы **остаётся таким же, как до операции**.  
   - Пример: `std::vector::push_back()` (если move-конструктор `noexcept`).  

3. **Basic exception safety (базовая гарантия)**  
   - При исключении программа остаётся в **корректном состоянии**, но оно может измениться.  
   - Пример: `std::vector::insert()`, если элемент кидает исключение при копировании.  

4. **No guarantee (нет гарантий)**  
   - При исключении возможны **утечки памяти или неопределённое поведение (UB)**.  
   - Пример: `std::vector::operator[]` с выходом за границы (UB).  

---

## **2. Гарантии для основных операций**
### **`std::vector`**
| Операция               | Гарантия исключений                                                                 |
|------------------------|------------------------------------------------------------------------------------|
| `push_back()`          | **Strong**, если move-конструктор `noexcept`, иначе **Basic**                      |
| `emplace_back()`       | **Strong**, если конструктор `noexcept`, иначе **Basic**                           |
| `insert()`             | **Basic** (может оставить контейнер в изменённом состоянии)                        |
| `erase()`              | **No-throw** (деструкторы элементов не должны кидать исключения)                   |
| `clear()`              | **No-throw**                                                                       |
| `resize()`             | **Basic** (если конструктор по умолчанию/копирования кидает исключение)            |
| `reserve()`            | **Strong** (если аллокатор кидает исключение, старые данные не теряются)           |
| `operator[]`           | **No-throw** (если не выходит за границы)                                          |
| `at()`                 | **Strong** (кидает `std::out_of_range`, но не изменяет контейнер)                  |

### **`std::list`, `std::deque`, `std::forward_list`**
- `push_back()`, `push_front()`, `emplace_back()`, `emplace_front()` → **Strong** (если конструктор не кидает исключений).  
- `insert()`, `erase()` → **Basic** (если операции с элементами безопасны).  
- `clear()` → **No-throw**.  

### **`std::map`, `std::set`, `std::unordered_map`, `std::unordered_set`**
| Операция               | Гарантия исключений                                                                 |
|------------------------|------------------------------------------------------------------------------------|
| `insert()`             | **Strong** (если сравнение/хеширование не кидают исключений)                       |
| `emplace()`            | **Strong** (если конструктор `noexcept`)                                           |
| `erase()`              | **No-throw** (деструкторы элементов не должны кидать исключения)                   |
| `clear()`              | **No-throw**                                                                       |

---

## **3. Ключевые правила**
1. **Деструкторы контейнеров — `noexcept`**  
   - Если деструктор элемента кидает исключение — **программа завершается (`std::terminate`)**.  

2. **Аллокаторы должны быть безопасными**  
   - Если `allocate()` кидает исключение, контейнер **не должен терять данные**.  

3. **Move-операции должны быть `noexcept`**  
   - Иначе `std::vector` будет использовать копирование вместо перемещения (потеря производительности).  

4. **`std::vector::push_back` и `std::vector::emplace_back`**  
   - Если элемент нельзя скопировать/переместить **без исключений**, возможен **частично изменённый контейнер** (Basic guarantee).  

5. **Ассоциативные контейнеры (`map`, `set`)**  
   - `insert` и `emplace` имеют **Strong guarantee**, если **ключ не изменяется** при сравнении.  

---

## **4. Примеры**
### **Пример 1: `push_back` с Strong guarantee**
```cpp
std::vector<std::string> vec = {"a", "b", "c"};
vec.push_back("d");  // Strong guarantee (если move-конструктор `noexcept`)
```

### **Пример 2: `insert` с Basic guarantee**
```cpp
std::vector<MyClass> vec;
try {
    vec.insert(vec.begin(), MyClass(42));  // Если конструктор кидает исключение, вектор остаётся валидным, но состояние может измениться
} catch (...) {}
```

### **Пример 3: `erase` с No-throw guarantee**
```cpp
std::list<int> lst = {1, 2, 3};
lst.erase(lst.begin());  // Гарантированно не кидает исключений (если деструктор `int` безопасен)
```

## **5. Как писать безопасный код?**
1. **Используйте `noexcept` для move-конструкторов**  
   ```cpp
   class MyClass {
   public:
       MyClass(MyClass&& other) noexcept { ... }
   };
   ```

2. **Избегайте исключений в деструкторах**  
   ```cpp
   ~MyClass() noexcept { ... }  // Деструктор не должен кидать исключения!
   ```

3. **Проверяйте `capacity()` перед `push_back`**  
   ```cpp
   if (vec.capacity() == vec.size()) {
       vec.reserve(vec.size() * 2);  // Избегаем reallocation при `push_back`
   }
   vec.push_back(x);
   ```

4. **Используйте `try-catch` для опасных операций**  
   ```cpp
   try {
       myMap.insert({key, value});
   } catch (...) {
       // Обработка ошибки (например, откат изменений)
   }
   ```

---

## **Вывод**
- **No-throw**: `clear()`, `erase()`, `operator[]` (без проверки границ).  
- **Strong guarantee**: `push_back` (если `noexcept`), `insert` в ассоциативных контейнерах.  
- **Basic guarantee**: `insert`, `resize`, `push_back` (если нет `noexcept`).  
- **No guarantee**: Выход за границы (`operator[]` без проверки).  

**Совет:** Всегда проверяйте документацию для конкретного контейнера, так как гарантии могут зависеть от реализации.
