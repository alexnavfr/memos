### Примечания:
1. **Амортизированная сложность** (например, `push_back` в `vector`) означает, что большинство операций выполняются за O(1), но иногда происходит перевыделение памяти за O(n).
2. **Худший случай** в хеш-таблицах (`unordered_*`) наступает при плохой хеш-функции (коллизии).
3. **Адаптеры** (`stack`, `queue`, `priority_queue`) используют другие контейнеры внутри, поэтому их сложность зависит от базового контейнера.

### **2. Рекомендации по выбору контейнера (Use Cases)**

| **Когда использовать?** | **Рекомендуемый контейнер** | **Обоснование** |
|-------------------------|----------------------------|----------------|
| **Нужен быстрый доступ по индексу** | `std::vector`, `std::array` (если размер фиксирован) | Вектор обеспечивает O(1) доступ и кэш-дружественность. |
| **Частая вставка/удаление в начале и конце** | `std::deque` | Поддерживает O(1) вставку/удаление с обеих сторон. |
| **Частая вставка/удаление в середине** | `std::list` (если известна позиция) | O(1) вставка/удаление, но медленный доступ. |
| **LIFO (стек)** | `std::stack` (адаптер над `vector`/`deque`) | Оптимизирован для `push`/`pop` с конца. |
| **FIFO (очередь)** | `std::queue` (адаптер над `deque`/`list`) | Оптимизирован для `push` в конец и `pop` из начала. |
| **Очередь с приоритетом** | `std::priority_queue` (адаптер над `vector` + куча) | Быстрое извлечение максимума/минимума за O(log n). |
| **Уникальные элементы + сортировка** | `std::set` | Автоматическая сортировка, поиск за O(log n). |
| **Ассоциативный массив с сортировкой** | `std::map` | Хранение пар `ключ-значение` с сортировкой по ключу. |
| **Множество с быстрым поиском (без сортировки)** | `std::unordered_set` | Поиск за O(1) в среднем, но возможны коллизии. |
| **Ассоциативный массив с быстрым доступом (хеш-таблица)** | `std::unordered_map` | Быстрый доступ по ключу, но нет порядка. |

### **Выводы:**
- **Используйте `vector` по умолчанию**, если не нужны специфические операции (он самый быстрый для большинства сценариев).  
- **Если нужен порядок и поиск — `set`/`map`**, если важнее скорость — `unordered_set`/`unordered_map`.  
- **Если часто вставляете в начало — `deque` или `list`**, но `list` медленнее для доступа.  
- **Стек, очередь и приоритетная очередь** — используйте адаптеры (`stack`, `queue`, `priority_queue`).

### **Ключевые выводы по структурам:**
1. **Динамические массивы (`vector`, `deque`, `array`)**:
   - Используют непрерывную память → быстрый доступ, но вставка в середину требует сдвига.
   - `deque` — гибридная структура (блоки + указатели), поэтому поддерживает O(1) для операций с началом/концом.

2. **Списки (`list`, `forward_list`)**:
   - Нет произвольного доступа, но вставка/удаление за O(1) при известной позиции.
   - Используют указатели → фрагментированная память (медленный обход).

3. **Адаптеры (`stack`, `queue`, `priority_queue`)**:
   - Надстройки над другими контейнерами (по умолчанию `deque` или `vector` + куча).

4. **Ассоциативные контейнеры (`set`, `map`)**:
   - Балансируемые деревья (обычно красно-черные) → гарантированная O(log n) для всех операций.
   - Хеш-таблицы (`unordered_*`) → O(1) в среднем, но возможны коллизии (деградация до O(n)).

5. **Хеш-таблицы (`unordered_set`, `unordered_map`)**:
   - Используют бакеты и цепочки (списки или деревья) для разрешения коллизий.
   - Скорость зависит от хеш-функции и коэффициента заполнения.

### **Когда что выбирать?**
- **`vector`** — по умолчанию (кэш-эффективность, быстрый доступ).
- **`deque`** — если нужны операции с началом и концом.
- **`list`** — частые вставки/удаления в середину (но нет случайного доступа).
- **`set`/`map`** — если важен порядок элементов.
- **`unordered_set`/`unordered_map`** — если порядок не важен, а нужна максимальная скорость.

Для адаптеров (`stack`, `queue`) выбирайте базовый контейнер в зависимости от операций (например, `stack` на `vector`, `queue` на `deque`).
