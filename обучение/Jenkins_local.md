# Setup Jenkins localy
## Jennkins, GutHub Action, Docker...

### Prompt:
_Установка и настройка Jenkins локально. Предложить workflow разработки приложения используя git, cmake, qt, jenkins_
Установка и настройка Jenkins локально, а также создание workflow для разработки приложения с использованием Git, CMake, Qt и Jenkins, включает несколько шагов. Вот пошаговое руководство:

### Установка Jenkins

1. **Установка Java**:
   - Jenkins требует установленной Java. Убедитесь, что у вас установлена Java версии 8 или выше.

2. **Установка Jenkins**:
   - Скачайте последнюю версию Jenkins с официального сайта.
   - Установите Jenkins, следуя инструкциям для вашей операционной системы.

3. **Запуск Jenkins**:
   - Запустите Jenkins, используя команду `java -jar jenkins.war` или следуя инструкциям для вашей ОС.
   - Откройте браузер и перейдите по адресу `http://localhost:8080`.

4. **Настройка Jenkins**:
   - Следуйте инструкциям на экране для завершения начальной настройки.
   - Установите необходимые плагины, такие как Git, CMake и другие.

### Настройка Workflow

1. **Создание нового проекта**:
   - В Jenkins создайте новый проект типа "Freestyle project" или "Pipeline".

2. **Настройка исходного кода**:
   - В разделе "Source Code Management" выберите Git и укажите URL вашего репозитория.

3. **Настройка сборки**:
   - В разделе "Build" добавьте шаг "Execute shell" или "Execute Windows batch command" (в зависимости от вашей ОС).
   - В этом шаге добавьте команды для сборки вашего проекта с использованием CMake и Qt. Пример:
     ```bash
     mkdir build
     cd build
     cmake ..
     make
     ```

4. **Настройка тестирования**:
   - Если у вас есть тесты, добавьте шаг для их запуска. Например:
     ```bash
     cd build
     make test
     ```

5. **Настройка уведомлений**:
   - Настройте уведомления по электронной почте или другим способом, чтобы получать оповещения о статусе сборки.

### Пример Pipeline

Если вы используете Jenkins Pipeline, ваш `Jenkinsfile` может выглядеть так:

```groovy
pipeline {
    agent any

    stages {
        stage('Checkout') {
            steps {
                git 'https://your-git-repo-url.git'
            }
        }
        stage('Build') {
            steps {
                sh '''
                mkdir build
                cd build
                cmake ..
                make
                '''
            }
        }
        stage('Test') {
            steps {
                sh '''
                cd build
                make test
                '''
            }
        }
    }

    post {
        always {
            echo 'Pipeline completed.'
        }
        success {
            echo 'Pipeline succeeded.'
        }
        failure {
            echo 'Pipeline failed.'
        }
    }
}
```

### Заключение

Этот workflow позволяет автоматизировать процесс сборки и тестирования вашего приложения с использованием Jenkins, Git, CMake и Qt. Вы можете адаптировать его под свои нужды, добавляя дополнительные шаги или изменяя существующие.

   - Установите Java с помощью Homebrew:



### Артефакты Jenkins

Артефакты в Jenkins — это файлы, созданные в процессе выполнения сборки, которые могут быть полезны для дальнейшего использования или анализа. Это могут быть исполняемые файлы, библиотеки, отчеты о тестировании, логи и другие данные. Артефакты сохраняются на сервере Jenkins и могут быть скачаны или использованы в последующих сборках.

**Примеры артефактов:**
- Скомпилированные бинарные файлы.
- Отчеты о тестировании.
- Логи сборки.
- Пакеты для развертывания.

**Как сохранить артефакты в Jenkins:**
- В настройках проекта Jenkins, в разделе "Post-build Actions", можно добавить шаг "Archive the artifacts" и указать путь к файлам, которые нужно сохранить.

### Связь между Docker, Jenkins и GitHub Actions

**Docker:**
- Docker используется для создания контейнеров, которые обеспечивают изолированную среду для выполнения приложений.
- Jenkins может использовать Docker для запуска сборок в контейнерах, что обеспечивает консистентность среды и упрощает управление зависимостями.
- Docker-контейнеры могут быть использованы для развертывания приложений, собранных с помощью Jenkins или GitHub Actions.

**Jenkins:**
- Jenkins — это инструмент для непрерывной интеграции и доставки (CI/CD), который автоматизирует процесс сборки, тестирования и развертывания приложений.
- Jenkins может быть настроен для запуска в Docker-контейнере, что упрощает его развертывание и масштабирование.
- Jenkins может интегрироваться с GitHub для автоматического запуска сборок при изменении кода.

**GitHub Actions:**
- GitHub Actions — это встроенный в GitHub инструмент CI/CD, который позволяет автоматизировать рабочие процессы непосредственно в репозитории.
- GitHub Actions может использоваться как альтернатива Jenkins для автоматизации сборок, тестирования и развертывания.
- GitHub Actions может использовать Docker для выполнения задач в контейнерах, обеспечивая изоляцию и консистентность среды.

### Взаимодействие:

- **Docker** предоставляет изолированные контейнеры, которые могут использоваться как Jenkins, так и GitHub Actions для выполнения сборок и тестов.
- **Jenkins** может быть настроен для автоматического запуска сборок при изменении кода в GitHub, используя вебхуки.
- **GitHub Actions** может выполнять те же задачи, что и Jenkins, но непосредственно внутри GitHub, что упрощает настройку и управление.

Все три инструмента могут использоваться вместе или по отдельности в зависимости от требований проекта и предпочтений команды.
