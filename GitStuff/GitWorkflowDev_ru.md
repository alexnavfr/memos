# Разработка (git workflow) и контроль версий

## Prompt:
_**Git**. Подготовь и подробно объясни работу над проектом с такими входными данными. Существует проект с веткой `main` локальная и удаленная версия одинаковы. Задача продолжать разработку в новой несушествующей пока ветке условно `dev1`. Разработка может затянутся, значит нужно сохранять изменения удаленно. Одновременно в ветке `main` возможны изменения. Регулярно изменения ветки `dev1` должны доставлятся в `main`. С этого момента ветки должны быть равны и разработка в ветке `dev1` может быть продолжена. Пошагово опиши действия разработчика из командной строки. Отдельным блоком расскажи те-же шаги, но при помощи VSCode._

Вот подробный план работы с Git над проектом с учётом всех условий:

---

## 💻 Командная строка (терминал)

### 📌 Исходные данные:

* Ветка `main` существует, локальная и удалённая версии синхронизированы.
* Нужно создать ветку `dev1`, работать в ней, пушить изменения.
* Периодически вливать `dev1` в `main` так, чтобы они были равны.

---

### 🔷 1. Создание и публикация новой ветки `dev1`

```bash
# Перейти на main и убедиться, что она обновлена
git checkout main
git pull origin main

# Создать новую ветку и перейти в неё
git checkout -b dev1

# Отправить ветку на сервер (удалённый репозиторий)
git push -u origin dev1
```

> `-u` связывает локальную ветку `dev1` с удалённой — удобно для будущих `push/pull`.

---

### 🔷 2. Работа в ветке `dev1`

```bash
# Редактируем код, добавляем новые файлы и изменения
git add .
git commit -m "Реализована фича X в dev1"

# Отправка изменений в удалённую ветку
git push
```

> Можно выполнять это регулярно, чтобы не потерять прогресс.

---

### 🔷 3. Обновление ветки `main` из `dev1` (слияние)

#### 💡 Когда нужно, чтобы `main` получила всё из `dev1` и сравнялась:

```bash
# Перейти на main
git checkout main

# Убедиться, что последняя версия с удалённого репозитория
git pull origin main

# Слить изменения из dev1
git merge dev1

# Отправить результат в удалённый main
git push origin main
```

---

### 🔷 4. Продолжение разработки в `dev1`

```bash
git checkout dev1
# Продолжаем разработку и повторяем шаги 2–3
```

---

### 🔷 5. Что если main изменился другими разработчиками?

Чтобы `dev1` был в курсе изменений из `main`:

```bash
# Находясь в dev1
git pull origin main
```

> Это обновит ветку `dev1` последними изменениями из `main`.

---

## 🧩 Вариант в виде последовательности команд

```bash
git checkout main
git pull origin main
git checkout -b dev1
git push -u origin dev1
# работа → git add . → git commit → git push
# ...
git checkout main
git pull origin main
git merge dev1
git push origin main
git checkout dev1
# (повторить по необходимости)
```

---

## 🧠 Общие советы:

* Перед `merge` всегда делайте `pull origin main`, чтобы избежать конфликтов.
* Для безопасности перед мержем используйте `git status` и `git log --oneline`.

## 🧰 Те же действия в **VSCode**

> Предполагается, что установлен Git и открыт репозиторий в VSCode.

---

### 1. 📁 Создание ветки `dev1`

* В левом нижнем углу нажмите на текущую ветку (`main`).
* В выпадающем меню выберите `Create new branch...` → введите `dev1`.
* Нажмите **"Publish Branch"** в верхней части интерфейса Source Control (если VSCode предложит).

---

### 2. 🔨 Работа и коммиты

* Редактируйте код.
* Перейдите на панель Source Control (иконка с инициалами).
* Введите сообщение коммита.
* Нажмите **✓ Commit**.
* Затем нажмите **… → Push** (или появится кнопка **Push** внизу экрана).

---

### 3. 🔁 Слияние `dev1` в `main`

* Смените ветку на `main` (внизу слева → выбрать `main`).
* Нажмите **… → Pull from... → origin/main**.
* Нажмите **… → Merge Branch → dev1**.
* После успешного слияния нажмите **Push**.

---

### 4. 🔄 Обновление `dev1` изменениями из `main`

* Перейдите на `dev1`.
* Нажмите **… → Pull from → origin/main**.

---

### 🔁 Повторяйте цикл:

* Работа в `dev1` → push.
* Слияние в `main` → push.
* Возврат в `dev1` → продолжение.

---

## ✅ Результат

После всех шагов:

* `dev1` — активная ветка для долгой разработки.
* `main` — периодически обновляется из `dev1`.
* Изменения из `main` также можно вносить обратно в `dev1`.

Если хочешь — могу сделать схему или bash-скрипт, который автоматизирует эти действия.

## 📌 **1. Схема ветвления и слияния `dev1` ↔ `main`**

```
  main (удалённая/локальная)
   │
   ▼
Создание ветки dev1
   │
   ▼
dev1 (долгая разработка)
   │
   ├── Коммит → push
   │
   ├── Коммит → push
   │
   ├── (при необходимости) ← pull из main
   │
   ▼
Пора влить dev1 → main
   │
   ▼
Переключиться на main
   │
   ├── pull origin main
   ├── merge dev1
   └── push origin main
   ▼
main теперь = dev1
   │
   ▼
Продолжение разработки в dev1 (повтор цикла)
```

> 💡 Одновременная разработка в `main` допускается, но изменения из неё периодически тянем в `dev1`, чтобы избежать конфликтов.

## ⚙️ **2. Bash-скрипт: git\_dev1\_helper.sh**

```bash
#!/bin/bash

# Названия веток
MAIN_BRANCH="main"
DEV_BRANCH="dev1"

echo "==== Git Dev Workflow Helper ===="
echo "Выберите действие:"
echo "1. Создать ветку $DEV_BRANCH от $MAIN_BRANCH"
echo "2. Переключиться на $DEV_BRANCH и запушить"
echo "3. Закоммитить и запушить изменения в $DEV_BRANCH"
echo "4. Слить $DEV_BRANCH в $MAIN_BRANCH и запушить main"
echo "5. Подтянуть изменения из $MAIN_BRANCH в $DEV_BRANCH"
echo "6. Выйти"
read -p "Ваш выбор: " choice

case $choice in
  1)
    git checkout $MAIN_BRANCH && git pull origin $MAIN_BRANCH
    git checkout -b $DEV_BRANCH
    echo "Ветка $DEV_BRANCH создана от $MAIN_BRANCH."
    ;;
  2)
    git checkout $DEV_BRANCH
    git push -u origin $DEV_BRANCH
    echo "Ветка $DEV_BRANCH опубликована."
    ;;
  3)
    git add .
    read -p "Введите сообщение коммита: " msg
    git commit -m "$msg"
    git push
    ;;
  4)
    git checkout $MAIN_BRANCH && git pull origin $MAIN_BRANCH
    git merge $DEV_BRANCH
    git push origin $MAIN_BRANCH
    echo "$DEV_BRANCH влит в $MAIN_BRANCH и отправлен на сервер."
    ;;
  5)
    git checkout $DEV_BRANCH
    git pull origin $MAIN_BRANCH
    echo "Изменения из $MAIN_BRANCH влиты в $DEV_BRANCH."
    ;;
  6)
    echo "Выход..."
    exit 0
    ;;
  *)
    echo "Неверный выбор."
    ;;
esac
```

---

### 🚀 Как использовать скрипт:

1. Сохрани файл:

```bash
nano git_dev1_helper.sh
```

2. Вставь код, нажми `Ctrl+O`, затем `Enter`, и `Ctrl+X` для выхода.

3. Сделай исполняемым:

```bash
chmod +x git_dev1_helper.sh
```

4. Запускай:

```bash
./git_dev1_helper.sh
```
