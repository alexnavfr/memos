# Git Hosting

## Prompt:
_Подготовь сводную сравнительную таблицу GitHub <->GitLab <-> Gitea <-> BitBucket <-> Git на домашнем сервере в локальной сети. Плюсы и минусы каждого кратко. Области применения. Подробный анализ каждого с Pros et Cons._

Вот сводная **сравнительная таблица** популярных решений для хостинга Git-репозиториев:

| Платформа                                       | Плюсы                                                                                                                               | Минусы                                                                                              | Области применения                               |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| **GitHub**                                      | – Самая популярная платформа<br>– Большое сообщество<br>– Actions (CI/CD)<br>– Множество интеграций<br>– Бесплатные приватные репо  | – Закрытый код<br>– Не на своём сервере<br>– Ограничения в бесплатном CI                            | Open-source проекты, команды, портфолио          |
| **GitLab (SaaS + Self-hosted)**                 | – Полноценный CI/CD встроен<br>– Open Source (CE)<br>– Поддержка DevOps цикла<br>– Возможность полной автономии                     | – Требователен к ресурсам при self-hosted<br>– Сложнее настроить, чем GitHub                        | Корпоративная разработка, self-hosting           |
| **Gitea**                                       | – Лёгкий и быстрый<br>– Open Source<br>– Просто хостить на своём сервере<br>– Низкие требования к ресурсам                          | – Меньше возможностей по сравнению с GitLab<br>– Ограниченный CI/CD (через внешние инструменты)     | Локальная разработка, малые команды, self-hosted |
| **Bitbucket (Cloud + Server)**                  | – Поддержка Mercurial (ранее)<br>– Интеграция с Jira и Atlassian<br>– Pipelines (CI/CD)<br>– Поддержка LFS                          | – Менее популярен, чем GitHub<br>– Ограничения в бесплатной версии<br>– Меньше open source проектов | Разработка в Atlassian-экосистеме, команды       |
| **Git на локальном сервере (bare репозитории)** | – Полный контроль<br>– Безопасность (без выхода в интернет)<br>– Максимальная кастомизация<br>– Нет зависимости от внешних сервисов | – Нет UI по умолчанию<br>– Требует настройки доступа, прав<br>– Нет встроенного CI/CD               | Интранет, защита данных, образовательные проекты |

### Подробный анализ

---

### 🔵 **GitHub**

#### ✅ Плюсы:

* **Масштаб** — миллионы проектов, развитая экосистема.
* **GitHub Actions** — встроенный CI/CD.
* **GitHub Pages** — хостинг сайтов.
* **Интеграции** — Copilot, Codespaces, Slack, Discord.
* **Pull Requests и Code Review** — интуитивный интерфейс.

#### ❌ Минусы:

* **Закрытая платформа** — нельзя полноценно self-host.
* **Зависимость от Microsoft**.
* **Ограничения в бесплатном CI/CD (2000 минут/месяц)**.
* **Нет офлайн-режима**.

#### 🔧 Область применения:

* Open-source, портфолио, быстрый старт.
* Командная разработка с фокусом на внешние сервисы.

---

### 🔴 **GitLab**

#### ✅ Плюсы:

* **Полноценный DevOps**: CI/CD, Issue Board, мониторинг.
* **Self-hosted Community Edition — open source**.
* **Fine-grained права доступа**.
* **Поддержка Docker/Kubernetes** из коробки.

#### ❌ Минусы:

* **Требовательность к ресурсам** (RAM, CPU).
* **Сложность установки и обновления (особенно Omnibus)**.
* **Интерфейс менее отзывчивый, чем у GitHub**.

#### 🔧 Область применения:

* Внутренние корпоративные проекты, CI/CD pipeline внутри компании.
* Строгая изоляция и контроль инфраструктуры.

---

### 🟢 **Gitea**

#### ✅ Плюсы:

* **Очень лёгкий** — запускается даже на Raspberry Pi.
* **Open Source**, быстрый старт.
* **Веб-интерфейс прост и понятен**.
* **Плагинная архитектура (в Gitea >= 1.18)**.

#### ❌ Минусы:

* **Мало встроенных DevOps-фич**.
* **Потребуются внешние инструменты для CI/CD** (например, Drone CI, Woodpecker).
* **Менее популярный — меньше материалов и интеграций**.

#### 🔧 Область применения:

* Индивидуальная или командная разработка на своём сервере.
* Локальные проекты, обучающие среды.

---

### 🟠 **Bitbucket**

#### ✅ Плюсы:

* **Интеграция с Jira/Confluence**.
* **Bitbucket Pipelines — встроенный CI/CD**.
* **Поддержка self-hosted версии (Bitbucket Server/Data Center)**.
* **Поддержка LFS и IP Whitelisting**.

#### ❌ Минусы:

* **Ограниченный бесплатный план**.
* **Менее популярен в open source**.
* **Слабее сообщество, чем у GitHub и GitLab**.

#### 🔧 Область применения:

* Команды, использующие Atlassian stack.
* Проекты с высокой интеграцией в Jira.

---

### ⚫ **Git на локальном сервере (bare репозитории)**

#### ✅ Плюсы:

* **Полный контроль** — данные не покидают сеть.
* **Минимальные требования** — можно поднять на любом сервере.
* **Можно кастомизировать любые аспекты (доступ, скрипты)**.

#### ❌ Минусы:

* **Нет веб-интерфейса** (если не добавить его — напр. cgit, GitWeb).
* **Нет CI/CD, Issue tracker и т.п.**.
* **Администрирование и резервное копирование — вручную**.

#### 🔧 Область применения:

* Внутренние репозитории, лаборатории, защищённые разработки.
* Обучение Git на низком уровне.
