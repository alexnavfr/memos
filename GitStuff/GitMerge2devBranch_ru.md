# Merge 2 dev branches

## Prompt:
_Git. Как безопасно сделать мерж ветки dev1 в ветку dev1. Обе ветки ветки разработки. Пошагово_

Ниже **безопасный, классический способ** сделать merge **`dev1` → `dev`** (предполагаю, что опечатка в вопросе и ветки разные 🙂).

Цель:

> взять изменения из `dev1` и аккуратно влить их в `dev`, не потеряв код и с возможностью отката.

---

## 0. Общая идея (коротко)

* **переходим в ветку, в которую мержим** (`dev`)
* **обновляем её**
* **делаем merge**
* **разрешаем конфликты (если есть)**
* **проверяем и коммитим**

---

## 1. Проверяем текущее состояние репозитория

```bash
git status
```

Важно:

* рабочее дерево **чистое** (нет незакоммиченных файлов)
* если есть изменения → либо `commit`, либо `stash`

---

## 2. Переключаемся в целевую ветку (`dev`)

```bash
git checkout dev
```

или (новый синтаксис):

```bash
git switch dev
```

---

## 3. Обновляем `dev` из удалённого репозитория

```bash
git pull origin dev
```

👉 Это важно:
ты мержишь **актуальную** ветку, а не устаревшую.

---

## 4. (Рекомендуется) Смотрим, что будет в мерже заранее

```bash
git log --oneline --graph --decorate --all
```

или

```bash
git diff dev..dev1
```

Чтобы понимать масштаб изменений.

---

## 5. Делаем сам merge

```bash
git merge dev1
```

### Возможные варианты:

#### ✅ Вариант 1: конфликтов нет

Git:

* автоматически создаст merge-коммит
* всё готово

Переходи к шагу **8**

---

#### ⚠️ Вариант 2: есть конфликты

Git напишет:

```
CONFLICT (content): Merge conflict in ...
```

---

## 6. Разрешаем конфликты

Открываешь конфликтный файл, увидишь:

```text
<<<<<<< HEAD
код из dev
=======
код из dev1
>>>>>>> dev1
```

Твоя задача:

* оставить нужный код
* удалить **все** `<<<<<<< ======= >>>>>>>`

После исправления:

```bash
git add конфликтный_файл.cpp
```

Повторить для всех конфликтов.

---

## 7. Завершаем merge

Если Git не сделал коммит сам:

```bash
git commit
```

(сообщение можно оставить стандартное)

---

## 8. Проверяем результат

```bash
git status
```

Должно быть:

```
nothing to commit, working tree clean
```

Запусти:

* сборку
* тесты
* приложение

---

## 9. Отправляем результат в удалённый репозиторий

```bash
git push origin dev
```

---

# 🛡️ Дополнительные меры безопасности (очень советую)

### 🔹 Вариант A: сделать backup-ветку

```bash
git checkout dev
git branch dev_backup_before_merge
```

Если что-то пошло не так:

```bash
git reset --hard dev_backup_before_merge
```

---

### 🔹 Вариант B: dry-run (через `--no-commit`)

```bash
git merge dev1 --no-commit --no-ff
```

* Git применит изменения
* но **не создаст коммит**
* можно посмотреть результат
* если не нравится:

```bash
git merge --abort
```

---

## ⚠️ Частые ошибки

❌ Мержить, находясь в `dev1`
❌ Делать merge с грязным рабочим деревом
❌ Не делать `git pull` перед merge
❌ Паниковать при конфликтах 🙂
