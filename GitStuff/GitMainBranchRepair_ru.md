# Git Востановление скомпрометированной ветки `master/main`

## Prompt:
_Git 2.19. Как правильно восстановить испорченную локальную версию ветки `master`?_

*Variant 1*
---

Для восстановления испорченной локальной ветки `master` в Git 2.19 есть несколько надежных способов. Вот пошаговые инструкции:

## 🔍 **Сначала оцените ситуацию**

```bash
# Проверьте текущее состояние
git status
git log --oneline -10
git reflog
```

## 🔄 **Способ 1: Использование reflog (наиболее безопасный)**

1. **Найдите последнюю рабочую коммит в reflog:**
```bash
git reflog master
# или просто
git reflog
```
Ищите запись типа `master@{n}` с комментарием типа `commit: ваш комментарий`

2. **Восстановите master на этот коммит:**
```bash
git reset --hard master@{n}
# или если знаете хэш коммита
git reset --hard abc1234
```

## 🔄 **Способ 2: Использование ORIG_HEAD**

Если порча произошла после слияния или перезаписи:
```bash
git reset --hard ORIG_HEAD
```

## 🔄 **Способ 3: Если есть удаленная ветка**

1. **Получите свежую версию с удаленного репозитория:**
```bash
git fetch origin
```

2. **Сбросьте локальную ветку:**
```bash
git reset --hard origin/master
```

## ⚠️ **Важные предупреждения**

- **`--hard` удалит незакоммиченные изменения** в рабочей директории!
- Если есть незакоммиченные изменения, которые нужно сохранить:
```bash
# Сначала сохраните изменения
git stash
# Выполните восстановление
git reset --hard ...
# Верните изменения
git stash pop
```

## 💾 **Если ничего не помогло**

Если ветка полностью испорчена и нет ссылок:
```bash
# Найдите потерянные коммиты
git fsck --lost-found
# Проверьте dangling коммиты
git log --oneline $(git fsck --lost-found | grep commit | cut -d' ' -f3)
```

## 🛡️ **Профилактика на будущее**

1. Настройте автобэкап:
```bash
# В .git/config или .gitconfig
[alias]
    backup = "!git branch backup-master-$(date +%Y%m%d-%H%M%S) master"
```

2. Перед опасными операциями создавайте временную ветку:
```bash
git branch backup-before-operation
```

**Рекомендую начинать со Способа 1 (reflog)**, так как он не зависит от удаленного репозитория и показывает всю историю изменений указателя ветки.

## 🗑️ **Восстановление через удаление локальной ветки `master`**

Этот метод работает, если у вас есть **актуальная версия в удаленном репозитории** (origin/master).

### 🔄 **Способ 1: Простое удаление и пересоздание**

```bash
# 1. Переключитесь на другую ветку (если сейчас на master)
git checkout другая-ветка

# 2. Удалите испорченный локальный master
git branch -D master

# 3. Пересоздайте master из origin/master
git checkout -b master origin/master
```

### 🔄 **Способ 2: Форсированный сброс (без переключения ветки)**

```bash
# Если вы уже на ветке master:
# 1. Сначала убедитесь, что есть свежая версия в origin
git fetch origin

# 2. Удалите текущую ветку master
git checkout --detach  # перейти в detached HEAD
git branch -D master

# 3. Создайте новую ветку master из origin/master
git checkout -b master origin/master
```

### 🔄 **Способ 3: Через полный сброс upstream**

```bash
# Полный сброс локальной ветки к удаленной
git fetch origin
git reset --hard origin/master
git clean -fd  # удалит неотслеживаемые файлы
```

## ⚠️ **Критически важные моменты**

### **Перед удалением проверьте:**
```bash
# Убедитесь, что удаленная ветка актуальна
git fetch origin
git log --oneline origin/master -5
```

### **Если в удаленной ветке тоже проблемы:**
```bash
# Создайте временную резервную копию
git branch backup-master-испорченный master
```

### **Если есть незакоммиченные изменения:**
```bash
# 1. Сохраните изменения
git stash

# 2. Удалите и восстановите master
git checkout другую-ветку
git branch -D master
git checkout -b master origin/master

# 3. Верните изменения
git stash pop
```

## 🎯 **Рекомендуемый алгоритм:**

```bash
# 1. Сохраняем текущее состояние (на всякий случай)
git branch backup-master-$(date +%Y%m%d) master

# 2. Получаем свежие данные с удаленного репозитория
git fetch --all --prune

# 3. Переключаемся на другую ветку
git checkout develop  # или любая другая существующая ветка

# 4. Удаляем испорченный master
git branch -D master

# 5. Восстанавливаем из origin
git checkout -b master origin/master

# 6. Проверяем
git status
git log --oneline -5
```

## ❌ **Когда этот метод НЕ подходит:**

1. **Если удаленная ветка origin/master отсутствует или устарела**
2. **Если у вас есть важные коммиты только в локальном master**
3. **Если вы работали без удаленного репозитория**

## 🔄 **Альтернатива без полного удаления:**

Если не хотите удалять ветку полностью, можно сделать "мягкий сброс":

```bash
# Сбросить master к origin/master без удаления ветки
git checkout master
git reset --hard origin/master
```

## 💡 **Вывод:**
Удаление локальной ветки `master` — **безопасный метод только при наличии актуального origin/master**. Всегда делайте backup перед удалением и проверяйте, что в удаленной ветке есть все нужные коммиты.
