# Git Merge Steps

## Prompt:
_Git. MacOs Catalina. Моделируем ситуацию. Есть 2 ветки 'main' и 'dev'. В обоих есть файл 'toto.md'. Файл изменялся одновременно несколька раз в каждой ветке. 2 изменения одинаковы, третье в одной строке но разные. Мы должны доставить изменения из 'dev' в 'main' предварительно приведя 'dev' в соответствие с  'main'. Оба изменения в файле 'toto.md' правильные и должны быть приняты. Вариант 1-сначала main потом dev. Вариант 2 последовательность другая. Распиши последовательно шаги для консоли. Для GUI(рассмотри различные клиенты и IDE)._

Рассмотрим, как смоделировать и разрешить ситуацию слияния веток `main` и `dev`, в которых файл `toto.md` изменялся независимо. Предположим:

* В обеих ветках сделаны 3 изменения.
* Два изменения одинаковые.
* Одно изменение касается **той же строки**, но **разное по содержанию**.
* Мы хотим, чтобы **все изменения** были приняты.
* Цель: **влить изменения из `dev` в `main`**, предварительно приведя `dev` в соответствие с `main`.

---

## 🔧 Вариант 1. Работа через консоль (CLI)

### Шаги (сначала `main`, потом `dev`)

```bash
# 1. Переключаемся на ветку main
git checkout main

# 2. Обновляем main (если работаем в команде)
git pull origin main

# 3. Переключаемся на ветку dev
git checkout dev

# 4. Подтягиваем изменения из main в dev (слияние)
git merge main
```

> ⚠️ На этом этапе возникнет конфликт в `toto.md`, если строки различаются.

```bash
# 5. Редактируем файл toto.md вручную
nano toto.md  # или любой редактор

# 6. Удаляем конфликтные маркеры:
# <<<<<<< HEAD
# изменения из dev
# =======
# изменения из main
# >>>>>>> main
# Объединяем вручную так, чтобы сохранить и то и другое.

# 7. Помечаем файл как разрешённый
git add toto.md

# 8. Завершаем merge
git commit

# 9. Теперь dev приведён к соответствию с main и содержит все нужные изменения.

# 10. Переключаемся на main
git checkout main

# 11. Вливаем dev в main
git merge dev

# 12. Если всё ок, пушим
git push origin main
```

---

## 🔄 Вариант 2. Сначала `dev`, потом `main`

Этот способ наоборот: сначала в `main` вливаем `dev`, а затем уже разбираем конфликты там.

```bash
git checkout main
git pull origin main

# Вливаем dev в main
git merge dev
```

> Возникает конфликт в `toto.md`.

```bash
nano toto.md  # или другой редактор

# Разрешаем конфликт, объединяя вручную изменения

git add toto.md
git commit

git push origin main
```

---

## ✅ Какой вариант лучше?

* **Вариант 1 (merge main → dev)** позволяет сначала привести `dev` к свежему состоянию, убедиться, что всё работает, и только потом вливать в `main`.
* **Вариант 2 (merge dev → main)** быстрее, но может нарушить `main`, если что-то пойдёт не так при разрешении конфликтов.

💡 Рекомендуется **Вариант 1**, особенно если `main` — продакшн-ветка.

## 🖼️ GUI-клиенты

### 🔹 GitKraken

1. Открыть проект.
2. Checkout `dev`.
3. Перетащить `main` на `dev`, выбрать **merge into dev**.
4. При конфликте откроется интерфейс разрешения:

   * GitKraken показывает "ours" и "theirs".
   * Объедините вручную, сохраните.
   * Commit merge.
5. Перетащить `dev` на `main`, merge.
6. Push.

---

### 🔹 Sourcetree

1. Checkout `dev`.
2. Правый клик на `main` → Merge into current branch.
3. При конфликте:

   * Используйте встроенный конфликторазрешатель или внешний (например, KDiff3, Meld).
4. После успешного merge:

   * Commit.
5. Переключиться на `main`.
6. Merge `dev` → `main`.
7. Push.

---

### 🔹 VS Code (с Git интеграцией)

1. Открыть проект, переключиться на `dev`.
2. В `Source Control` → кнопка `...` → Merge branch → выбрать `main`.
3. При конфликте:

   * Откроется редактор с конфликтами.
   * Выберите "Accept Both Changes" или вручную объедините.
4. Сохранить, затем Stage Changes → Commit.
5. Переключиться на `main`, выполнить merge `dev`.
6. Push.

---

### 🔹 CLion / Rider / WebStorm (JetBrains)

1. Переключиться на ветку `dev`.
2. VCS → Git → Merge Changes → выбрать `main`.
3. Если конфликт:

   * JetBrains покажет визуальный трёхсторонний merge.
   * Объедините изменения, нажмите Apply.
4. Commit.
5. Снова VCS → Git → Merge Changes → выбрать `dev` на ветке `main`.
6. Push.
