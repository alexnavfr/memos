# GitHub терминология

## Prompt:
_Вначале разберем термины GitHub. Что такое 'Project' и 'Repository' в терминах GitHub. Разница и сходство. Когда и как использовать._

На GitHub термины **Project** и **Repository** обозначают разные сущности, хотя они могут пересекаться в использовании. Разберем их подробно, включая сходства, различия и сценарии использования.

### **Repository (Репозиторий)**

**Определение**: Репозиторий — это основная единица хранения данных на GitHub. Это место, где хранятся файлы проекта, история изменений (коммиты), ветки, теги и другие данные, связанные с версионным контролем Git. Репозиторий можно рассматривать как папку с файлами и их историей.

**Основные характеристики**:
- Содержит код, документацию, конфигурационные файлы и другие ресурсы проекта.
- Использует систему контроля версий Git для отслеживания изменений.
- Может быть публичным, приватным или внутренним (для организаций).
- Поддерживает ветвление (branches), запросы на включение (pull requests), управление issues и действиями (GitHub Actions).
- Каждый репозиторий — это независимый проект или модуль с собственной историей.

**Когда использовать**:
- Когда вы хотите хранить и управлять кодом, файлами и их версиями.
- Для совместной работы над кодом с использованием веток и pull requests.
- Для публикации open-source проектов или хранения приватных проектов.
- Пример: Вы создаете веб-приложение и хотите хранить его код, файлы конфигурации и документацию в одном месте с историей изменений.

**Пример использования**:
1. Создаете репозиторий `my-web-app`.
2. Добавляете файлы (например, `index.html`, `style.css`, `README.md`).
3. Делаете коммиты, создаете ветки для новых функций, отправляете pull requests для их интеграции.
4. Используете issues для отслеживания задач и багов.

---

### **Project (Проект)**

**Определение**: Проект на GitHub — это инструмент для управления задачами и планирования работы, связанной с одним или несколькими репозиториями. Это, по сути, доска задач (в стиле Kanban или таблица), которая помогает организовать работу, отслеживать прогресс и управлять задачами.

**Основные характеристики**:
- Представляет собой визуальную доску с колонками (например, "To Do", "In Progress", "Done").
- Может быть привязан к одному или нескольким репозиториям или существовать независимо (на уровне пользователя или организации).
- Позволяет создавать задачи (issues), заметки, привязывать pull requests и отслеживать их статус.
- Подходит для планирования спринтов, управления backlog или координации работы команды.
- Не хранит код или файлы, а лишь организует связанные с ними задачи.

**Когда использовать**:
- Когда нужно организовать задачи и управлять рабочим процессом для проекта, особенно если он охватывает несколько репозиториев.
- Для планирования релизов, спринтов или крупных фич.
- Для визуального отслеживания прогресса (например, в стиле Kanban).
- Пример: Вы работаете над проектом, который включает несколько репозиториев (frontend, backend, API), и хотите видеть общий прогресс задач.

**Пример использования**:
1. Создаете проект `Website Redesign` на уровне организации.
2. Добавляете колонки: "Backlog", "In Progress", "Review", "Done".
3. Связываете задачи (issues) из репозиториев `frontend` и `backend`, а также добавляете заметки для планирования.
4. Перемещаете задачи между колонками по мере их выполнения.

---

### **Сходства**
1. **Связь с проектами**: Оба используются для организации работы над проектами, но на разных уровнях (репозиторий — код, проект — задачи).
2. **Интеграция на GitHub**: Проекты могут быть связаны с репозиториями, а задачи (issues) из репозитория могут отображаться на доске проекта.
3. **Командная работа**: Поддерживают совместную работу, включая доступ для нескольких пользователей.
4. **Гибкость**: Могут использоваться как для небольших, так и для крупных проектов.

---

### **Различия**
| **Характеристика**       | **Repository**                              | **Project**                                |
|--------------------------|---------------------------------------------|--------------------------------------------|
| **Назначение**           | Хранит код, файлы и историю изменений.      | Организует задачи и управляет рабочим процессом. |
| **Содержимое**           | Файлы, коммиты, ветки, pull requests.       | Доски Kanban, таблицы, задачи, заметки.    |
| **Связь**                | Самодостаточен, может быть связан с проектом. | Обычно связан с одним или несколькими репозиториями. |
| **Инструмент**           | Git (версионный контроль).                 | Kanban/таблицы (управление задачами).      |
| **Пример**             | Хранилище кода для приложения.             | План спринта для релиза приложения.        |

---

### **Когда и как использовать**
- **Repository**:
  - Создавайте репозиторий для каждого отдельного проекта или модуля, где нужен код, файлы или документация.
  - Используйте для хранения исходного кода, автоматизации (через GitHub Actions) и совместной работы над кодом.
  - Подходит для разработчиков, которые пишут код и хотят отслеживать его изменения.

- **Project**:
  - Создавайте проект, когда нужно управлять задачами, планировать этапы работы или координировать усилия между несколькими репозиториями.
  - Используйте для визуализации рабочего процесса (Kanban-доски) или планирования (например, для релиза или спринта).
  - Подходит для менеджеров проектов, разработчиков и команд, которым нужна общая картина задач.

**Комбинированное использование**:
- Часто проекты и репозитории используются вместе. Например, вы создаете репозиторий для кода приложения, а проект — для планирования задач (issues) и отслеживания прогресса. Issues из репозитория автоматически отображаются в проекте, что упрощает управление.

---

### **Пример сценария**
Допустим, вы разрабатываете веб-приложение:
1. Создаете репозиторий `my-app`, где храните код, документацию и настройки.
2. Внутри репозитория создаете issues для задач (например, "Добавить авторизацию", "Исправить баг в UI").
3. Создаете проект `App Development`, чтобы организовать эти задачи в Kanban-доске, добавив колонки для этапов работы.
4. Связываете issues из репозитория с проектом, чтобы отслеживать прогресс, и добавляете заметки для идей или встреч.

---

### **Итог**
- **Репозиторий** — это место для хранения кода и работы с ним.
- **Проект** — это инструмент для управления задачами и планирования.
- Используйте **репозиторий** для кода и версионного контроля, а **проект** — для организации и визуализации задач. Вместе они помогают эффективно управлять разработкой.
