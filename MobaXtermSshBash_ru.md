# MobaXterm + ssh + bash

## Prompt:
_MobaXterm. Ssh. как сохранить историю bash команд между ssh сессиями._

Чтобы сохранять историю команд Bash между SSH-сессиями в MobaXterm, нужно настроить Bash на удалённом сервере и проверить несколько ключевых моментов.

### ⚙️ Настройка истории команд Bash на сервере

Отредактируйте файл `~/.bashrc` в вашей домашней директории на удалённом сервере. Добавьте или раскомментируйте следующие строки:

```bash
# Append to the history file, don't overwrite it
shopt -s histappend

# Set large history size
HISTSIZE=10000
HISTFILESIZE=20000

# Save commands with timestamp
HISTTIMEFORMAT="%F %T "

# Ignore duplicate commands and those starting with space
HISTCONTROL=ignoreboth

# Save history immediately after each command
PROMPT_COMMAND="history -a; $PROMPT_COMMAND"
```

После внесения изменений примените новые настройки с помощью команды `source ~/.bashrc` или перезайдите в SSH-сессию.

### 🔎 Проверка прав доступа и других причин

Если история по-прежнему не сохраняется, проверьте:

- **Права доступа к файлу истории**: Файл `~/.bash_history` должен принадлежать вам, а не root. Проверьте это командой `ls -la ~/.bash_history`. Если владелец — root, исправьте это: `sudo chown ваш_логин:ваша_группа ~/.bash_history`.
- **Корректное завершение сессии**: История записывается в файл при нормальном завершении сессии (команда `exit`). При закрытии окна терминала сессия может завершиться некорректно, и история не успеет сохраниться. Настройка `PROMPT_COMMAND` решает эту проблему, сохраняя историю после каждой команды.

### 💡 Полезные команды для работы с историей

- `history` — показать всю историю команд.
- `history | grep ключевое_слово` — найти команды по ключевому слову.
- `!!` — повторить последнюю команду (удобно для `sudo !!`).
- `!номер` — выполнить команду из истории по её номеру.
- `history -c` — очистить историю в текущей сессии.

Настройки, которые вы внесёте в `~/.bashrc` на удалённом сервере, будут работать в любом SSH-клиенте, включая MobaXterm. Если проблема не решена, проверьте, используете ли вы на удалённом сервере именно Bash — другие оболочки (например, Zsh) хранят историю в других файлах.
